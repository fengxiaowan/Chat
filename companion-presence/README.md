# 小喵 · 在场陪伴（本地常驻小程序）

一个"轻"的在场陪伴工具：玩游戏、看影片时，按 `Ctrl + F1`，对着麦克风随口嘀咕一句，小喵就用语音回应你。不打扰，但知道她在。

## 怎么启动

**双击 `start.vbs`**（无黑窗，后台启动）。屏幕右上角会出现一个半透明的小圆点，表示她在。

> 想开机自启：把 `start.vbs` 的快捷方式放进
> `Win+R` → `shell:startup` 文件夹即可。

退出：在任务管理器结束 `powershell` 进程，或重启。

## 当前状态（重要，请先读）

**语音识别在这台机器上不稳定，尚未打通完整闭环。**

- ✅ 热键、置顶状态图标、后端对话、TTS 朗读，这些都已可用。
- ⚠️ **语音输入卡在最后一步**：本地语音识别读到的麦克风信号电平极低，识别时灵时不灵。

### 为什么卡住（诚实说明）

微信（Ctrl+Windows）等系统语音输入能正常用，是因为它们走 Windows 系统级语音引擎（WinRT / OneCore），那套引擎自带麦克风增益和降噪。但：

1. **WinRT 语音 API 要求「MSIX 包标识」**，普通 PowerShell/Python 脚本没有包标识，一调用就报错（`0x80131509`）。
2. **SAPI 8.0 桌面识别器**读不到英特尔智音麦克风（电平恒为 0）。
3. **Vosk 本地模型**虽然绕开了权限墙，能读到麦克风、能识别出内容，但读到的是**未经系统增益的裸信号**，电平太低（正常说话峰值约 0.01，应为 0.1~0.5），识别不稳定。

结论：这台机器上，本地脚本无法拿到系统那层麦克风增益/降噪，导致语音识别时灵时不灵。属于 Windows 平台的权限/驱动限制，不是代码 bug。

### 若想继续，可能的出路（未验证）

- 用 PowerShell 调用系统 WASAPI 音频增强（AudioGraph / Audio Enhancements）接口，把系统增益也应用到录音流——但同样可能撞包标识限制，成功率不确定。
- 换一台麦克风拾音正常、或系统语音引擎可用的机器。

## 原理

浏览器最小化/失焦后收不到全局按键、也拿不到麦克风，所以这部分用 Windows 原生能力（PowerShell + 本地语音识别）补上，对话逻辑仍然走已有的 8788 后端。

```
你按 Ctrl+F1  →  本地听你说一句  →  POST /liao/chat (SSE)  →  小喵回复
                ↑                                                  ↓
            置顶小圆点（状态）                          逐句 /liao/tts → 本地播放
```

## 状态机（对应小圆点）

| 状态 | 图标 | 说明 |
|---|---|---|
| 空闲 | 暗灰小点 | 等待你按快捷键，几乎看不见 |
| 听我说 | 蓝点 🎤 | 正在采集你的语音 |
| 发送等待 | 橙点 ⋯ | 识别完，正在等小喵回复 |
| 她在说 | 隐藏 | 她已经在说话了，不需要图标 |
| 说完再听几秒 | 淡蓝 🎤 | 她说完后，再听几秒你有没有补充 |
| 发送失败 | 红点 ! | 需要你知道 |
| 重连中 | 黄点 ↻ | 后端连不上，稍后自动重试 |

## 快捷键

默认 `Ctrl + F1`。可修改，见下方配置。

## 配置

配置写在 `presence.ps1` 顶部 `$cfg` 哈希表里：

| 字段 | 默认 | 说明 |
|---|---|---|
| `Hotkey` | `Ctrl+F1` | 全局快捷键。可改 `Ctrl+F12`、`Alt+F1` 等 |
| `ServerUrl` | `http://127.0.0.1:8788` | 后端地址 |
| `AuthUser` | `user` | 后端用户名 |
| `AuthPassword` | `111` | 后端密码 |
| `ListenMaxSec` | `12` | 单次录音最长秒数 |
| `SilenceSec` | `1.3` | 静音多少秒判定"说完了" |
| `AfterSpeakListen` | `4` | 她说完后再监听几秒 |
| `HistoryTurns` | `30` | 发给后端的历史条数 |
| `IconSize` | `36` | 图标直径（像素） |
| `IconMargin` | `14` | 图标离屏幕右上角距离 |

## 语音开关

默认会自动朗读她的回复。要关掉语音（只保留文字 + 图标），把 `presence.ps1` 里 `Send-And-Speak` 函数中的 `Speak-Text $txt` 一行注释掉即可。

## 文件说明

- `presence.ps1` — 主程序（全局热键 + 状态图标 + 对话 + 朗读）
- `listen_child.py` — 语音识别子进程（Python + Vosk 本地识别，每次识别单独起一个进程，识别完写结果文件就退出）
- `vosk-model/` — Vosk 中文识别模型（约 42MB，`listen_child.py` 依赖它）
- `start.vbs` — 双击启动器（无黑窗后台运行）

## 依赖

语音识别依赖本机已安装的 Python 环境：

- Python 解释器路径写在 `presence.ps1` 顶部 `$global:pythonExe`（当前指向 DSH 自带的 Python）。
- Python 包：`vosk`、`sounddevice`、`numpy`。
- 模型：`vosk-model/` 目录（`vosk-model-small-cn-0.22`）。

## 为什么识别要单独放子进程

语音识别放进一次性子进程：每次按快捷键就新起一个 `listen_child.py`，听 N 秒 → 结果写临时文件 → 子进程退出。主程序只轮询结果文件，完全不碰识别引擎。这样即使识别子进程出错，也只丢一次识别，主程序（热键 + 图标 + 对话）永远稳。
